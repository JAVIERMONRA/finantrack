Guía del aplicativo

Documentación del simulador FINANTRACK

Descripción del modelo, variables, fórmulas, criterios de decisión, uso y limitaciones.

1. Descripción del modelo

FINANTRACK es un simulador educativo para comparar tres alternativas de arquitectura de software para una aplicación de finanzas personales con OCR de recibos, PostgreSQL y un agente de IA. Evalúa un monolito modular, microservicios y una arquitectura orientada a eventos con los mismos valores de entrada.

El modelo calcula indicadores estimados de latencia p95, capacidad, disponibilidad, coste mensual, uso de CPU y puntuación global. Los resultados sirven para comparar opciones y explicar compromisos arquitectónicos.

2. Definición de variables

  • Usuarios activos diarios: volumen de usuarios que interactúan con la aplicación cada día.
  • Solicitudes por usuario/día: actividad media prevista por usuario.
  • Presupuesto mensual: límite económico disponible, expresado en pesos colombianos (COP).
  • Carga pico: solicitudes por segundo que se esperan en periodos de alta demanda.
  • Complejidad: mezcla estimada de operaciones sencillas, OCR y consultas de recomendación.
  • Crecimiento: porcentaje de aumento aplicado a la carga para estimar demanda futura.
  • Uso de IA externa: proporción de solicitudes que dependen de una API de IA.
  • Peso del coste: influencia relativa del coste en la puntuación final.
  • Latencia p95 objetivo y disponibilidad mínima: umbrales de calidad que se usan para evaluar restricciones.
  • Seguridad y equipo: condiciones que ajustan la idoneidad de cada alternativa.

3. Fórmulas principales

La carga futura se estima como cargaPico × (1 + crecimiento / 100). La complejidad normalizada es complejidad / 100 y la proporción de IA es usoIA / 100.

Para cada arquitectura, la capacidad se calcula como capacidadBase / (1 + complejidad × 0,8). La utilización estimada es cargaFutura / capacidad; la saturación añade penalización a la latencia cuando la utilización supera el 50 %.

La latencia estimada combina latencia base, complejidad, saturación, uso de IA y sobrecarga de red propia de cada arquitectura. La disponibilidad parte de un valor base y se reduce cuando existe sobrecarga. El coste mensual combina un coste fijo, un componente variable asociado a la carga y un coste operativo de cada alternativa.

La puntuación ponderada combina rendimiento, disponibilidad, seguridad, ajuste al tamaño del equipo y coste. El coste mensual estimado depende de la demanda futura, la complejidad de las operaciones y la proporción de solicitudes que usan IA. El presupuesto mensual es el límite disponible: no debe alterar artificialmente el coste del servicio, pero sí determina si una alternativa es viable y puede cambiar la recomendación. Las cifras son estimaciones del modelo.

4. Criterios de decisión

Una alternativa se considera compatible con las restricciones si cumple simultáneamente el objetivo de latencia, la disponibilidad mínima, el presupuesto y el requisito de seguridad seleccionado. Las alternativas que cumplen se priorizan; dentro de cada grupo se ordenan por puntuación. Si ninguna cumple todas las restricciones, se muestra el mejor compromiso disponible y se deben revisar las brechas.

5. Instrucciones de uso

  1. En Simulador, revisa los datos del proyecto y ajusta las variables y restricciones.
  2. Pulsa Ejecutar simulación para actualizar la recomendación, los indicadores y las gráficas.
  3. En Escenarios, usa los botones de escenarios predefinidos o guarda un escenario propio para comparar resultados.
  4. En Comparación, revisa las métricas y exporta los resultados a CSV.
  5. En Pruebas, pulsa Ejecutar las pruebas y revisa el resultado individual de cada caso, no solo el resumen.

6. Limitaciones

  • Es un modelo educativo determinista; sus cifras son estimaciones y no mediciones de infraestructura real.
  • No despliega ni conecta una aplicación real con PostgreSQL, OCR o la API de Claude Sonnet.
  • No sustituye pruebas de carga, análisis de seguridad, mediciones de costes de proveedores ni validación con datos reales.
  • Los resultados dependen de los coeficientes simplificados del modelo y de los valores introducidos por el usuario.
